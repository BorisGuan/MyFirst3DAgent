# Agent 架构价值导向升级方向记录

本文档记录下一阶段系统升级方向。排序方式不是按“最容易见效”或“短期影响大小”，而是按“架构价值”排序。目标是帮助后续逐步理解、逐步设计、逐步实现。

## 1. 价值排序

```text
1. 上下文管理体系
2. TaskObject / 状态生命周期架构
3. 可靠性与安全执行边界
4. 评估与反馈闭环
5. Operation 选择准确率
6. 参数准确率
7. 目标绑定准确率
8. Token / 缓存 / 成本优化
9. 测试与真实 Blender 验证矩阵
10. Composite / Sequence 能力
```

## 2. 上下文管理体系

这是 Agent 的核心能力之一，架构价值很高。

Agent 不是只处理一句话，它要理解：

```text
当前模型是什么
用户想做什么
项目风格是什么
之前做过什么
哪些 operation 可用
这次执行结果如何
下次怎么利用这些结果
```

后续可以升级成更完整的上下文体系：

```text
短期上下文
长期上下文
模型上下文
任务上下文
工具能力上下文
执行反馈上下文
用户偏好上下文
```

这部分很适合展示对 Agent 架构的理解，因为上下文管理是 Agent 和普通自动化脚本的重要区别之一。

## 3. TaskObject / 状态生命周期架构

这也是高价值方向。

它决定 Agent 不是随便调用工具，而是按状态流转：

```text
draft
validated
bound
planned
ready_to_execute
executing
completed / failed
```

后续可以继续强化：

```text
等待用户确认
失败重试
多轮修改
历史任务恢复
任务版本管理
```

这部分体现 state-based Agent architecture 的设计能力。

## 4. 可靠性与安全执行边界

这个方向体现生产级 Agent 思维。

重点不是“能不能执行”，而是：

```text
什么时候不能执行
失败了停在哪里
怎么保护源文件
怎么记录原因
怎么避免 LLM 乱调用 bpy
```

这块价值高，因为很多 Agent demo 缺少可靠性和安全边界。

## 5. 评估与反馈闭环

这是让 Agent 逐步变聪明的关键。

当前 report 主要用于记录结果。后续可以升级成：

```text
执行结果进入下一轮上下文
失败原因影响下一次 planning
用户反馈沉淀成偏好
参数效果形成经验
```

这比单纯增加功能更有架构价值。

## 6. Operation 选择准确率

这属于 planning 层能力优化。

它解决的问题是：

```text
用户这句话到底对应哪个 operation？
```

它和上下文管理强相关。上下文越清晰，operation selection 越稳定。

## 7. 参数准确率

参数准确率很实用，但架构价值略低于前几个方向。

它解决的问题是：

```text
选对 operation 之后，参数怎么更合适？
```

这会直接影响建模效果。

## 8. 目标绑定准确率

这个方向解决：

```text
到底修改哪个 Blender object？
```

对 3D Agent 很重要，但它更偏模型绑定和执行准备层。

## 9. Token / 缓存 / 成本优化

这是工程化价值方向。

可以优化：

```text
少传无关上下文
缓存 operation registry 摘要
缓存模型上下文摘要
缓存常见解析结果
按需检索上下文
```

它很有用，但通常应在上下文体系设计清楚之后再做。

## 10. 测试与真实 Blender 验证矩阵

这是工程可靠性方向。

它不一定是最高层架构，但对项目成熟度非常重要。后续应逐步从单个 real smoke 扩展到覆盖更多 atomic operations。

## 11. Composite / Sequence 能力

这个方向有潜力，但现在不应排太前。

它依赖前面的基础：

```text
上下文是否稳定
状态机是否够用
operation 是否准确
参数是否可靠
执行是否可验证
```

否则 sequence 只会把不稳定放大。

## 12. 当前建议优先关注

如果按架构价值排序，建议先关注前三个：

```text
1. 上下文管理体系
2. TaskObject / 状态生命周期架构
3. 可靠性与安全执行边界
```

其中最值得先讲、先设计、先写文档的是：

```text
上下文管理体系
```

原因是：上下文管理是 Agent 系统的核心能力之一，也是它区别于普通脚本自动化的重要标志。
